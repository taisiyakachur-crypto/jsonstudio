# JSON Studio

Локальна робоча станція для роботи з JSON. Порівняння, розбір довільного тексту в JSON,
таблиці, діаграми, форматування та валідація — все виконується у браузері, без бекенду.

> Проєкт побудовано поетапно (10 стадій, усі завершено — див. «Стан проєкту» нижче).

## Стек

Vite + React 18 + TypeScript (strict) · Tailwind CSS + shadcn/ui · Zustand (+ persist) ·
CodeMirror 6 · TanStack Table v8 · Recharts · json5 · jsonc-parser · ajv · jsonpath-plus ·
xlsx (лише запис) · Web Workers (Comlink) · @streamparser/json · idb-keyval · react-window ·
Vitest + React Testing Library.

## Розробка

Потрібен Node.js ≥ 20.

```bash
npm install
npm run dev
```

Інші команди:

```bash
npm run build         # продакшн-збірка у dist/
npm run preview       # локальний перегляд зібраного dist/
npm run test           # юніт-тести (Vitest)
npm run lint           # ESLint
npm run format         # Prettier
npm run gen:fixtures   # згенерувати тестові JSON-файли 5/20/50 МБ у scripts/fixtures/
```

## Деплой

Статична збірка (`dist/`), без бекенду. Готові конфігурації для двох платформ:

### GitHub Pages

Push у `main` автоматично збирає й публікує через `.github/workflows/deploy.yml`
(потрібно один раз увімкнути Pages: Settings → Pages → Source → **GitHub Actions**).

Workflow збирає з `VITE_BASE_PATH=/<назва-репозиторію>/` — це підходить для типової
project page (`https://<user>.github.io/<repo>/`). Якщо натомість деплоїте на user/org
page (`https://<user>.github.io/`), приберіть цей рядок env у workflow, щоб `base` лишався
`/` за замовчуванням.

Ручний білд з тим самим base path:

```bash
VITE_BASE_PATH=/<назва-репозиторію>/ npm run build
```

### Vercel

Нуль-конфіг: Vercel сам розпізнає Vite-проєкт. `vercel.json` додає лише SPA-рерайт (усі
шляхи → `index.html`, бо це клієнтський роутинг без сервера).

```bash
npx vercel        # прев'ю-деплой
npx vercel --prod # продакшн
```

`VITE_BASE_PATH` не потрібен — Vercel обслуговує з кореня домену.

### Перевірка воркерів у продакшн-збірці

Воркери (`new Worker(new URL('./x.worker.ts', import.meta.url), { type: 'module' })`)
збираються в окремі бандли й мають бути перевірені після справжньої збірки, не лише в
`npm run dev`:

```bash
npm run build && npm run preview
```

## PWA

`vite-plugin-pwa` генерує `manifest.webmanifest` + service worker. Стратегія кешування:
«мережа спочатку» для навігаційних запитів (`index.html`) — щоб оновлення застосунку
з'являлись одразу за наявності мережі; «кеш спочатку» для статичних ресурсів (скрипти,
стилі, шрифти, зображення, воркери). Після першого відкриття застосунок працює офлайн.
Іконки — `public/icons/` (192×192, 512×512, 512×512 maskable).

## Приватність

Жодних мережевих запитів із вмістом документів. Продакшн-збірка містить
`Content-Security-Policy` (`connect-src 'self'`), що блокує будь-які вихідні з'єднання
окрім самого застосунку.

## Безпека

`xlsx@0.18.5` (SheetJS з npm) має відомі high-severity вразливості (Prototype Pollution,
ReDoS) — обидві стосуються **читання/парсингу** файлів. Table використовує лише API
**запису** (`XLSX.utils.json_to_sheet` + `XLSX.write`) над даними, які вже розібрані
власним кодом застосунку — вразливий шлях читання ніколи не викликається.
