# JSON Studio

Локальна робоча станція для роботи з JSON. Порівняння, розбір довільного тексту в JSON,
таблиці, діаграми, форматування та валідація — все виконується у браузері, без бекенду.

> Проєкт будується поетапно (10 стадій). Цей README оновлюватиметься з кожним етапом;
> повна інструкція з деплою (GitHub Pages / Vercel) з'явиться на етапі 10.

## Стек

Vite + React 18 + TypeScript (strict) · Tailwind CSS + shadcn/ui · Zustand (+ persist) ·
CodeMirror 6 · TanStack Table · Recharts · Web Workers (Comlink) · idb-keyval · Vitest.

## Розробка

Потрібен Node.js ≥ 20.

```bash
npm install
npm run dev
```

Інші команди:

```bash
npm run build         # продакшн-збірка у dist/
npm run preview       # локальний перегляд зібраного dist/
npm run test           # юніт-тести (Vitest)
npm run lint           # ESLint
npm run format         # Prettier
npm run gen:fixtures   # згенерувати тестові JSON-файли 5/20/50 МБ у scripts/fixtures/
```

## Стан проєкту

- [x] Етап 1 — каркас: Vite/React/TS/Tailwind/shadcn, система вкладок з IndexedDB
      (`idb-keyval`) + localStorage (метадані), теми світла/темна, i18n uk/en,
      заглушки для всіх п'яти інструментів (Compare, Parse, Table, Chart, Format & Validate).
- [x] Етап 2 — інфраструктура великих файлів: Comlink-воркер (`src/workers/json-doc.worker.ts`)
      парсить JSON і віддає лише запитані гілки дерева, а не весь документ; файли > 20 МБ
      читаються порціями через `@streamparser/json` з прогрес-баром і робочим скасуванням;
      документи > 2 МБ показують банер «великий файл» + read-only перегляд перших ~2000
      рядків; віртуалізоване (`react-window`) дерево `JsonTree` довантажує дочірні вузли
      лише на розгортання/«завантажити ще». Скрипт `scripts/generate-fixtures.ts` генерує
      тестові файли на 5/20/50 МБ. Перевірено вручну: дерево 50 МБ відкривається (~1.5 с
      на цій машині) і плавно скролиться; повний бюджет продуктивності — етап 9.
- [x] Етап 3 — `JsonInput` (`src/components/json-input/`) + інструмент Format & Validate:
      редактор CodeMirror 6 з підсвіткою JSON, згортанням, пошуком (з `basicSetup`) і
      маркерами помилок (`@codemirror/lint`, дебаунс 300 мс); валідація в строгому режимі
      через `jsonc-parser` дає людську українську помилку з рядком/колонкою (наприклад
      «Рядок 8, колонка 20: коментарі недопустимі у строгому режимі JSON»), а м'який режим
      (JSON5) дозволяє коментарі/трейлінг-коми/неквотовані ключі. Formatувати (2/4/tab),
      мінімізувати, сортувати ключі рекурсивно, копіювати, очищати, вставити з буфера —
      усе теж працює. Документи > 2 МБ (файл або вставлений текст) автоматично перемикають
      `JsonInput` у той-таки режим великого файлу з етапу 2 (банер + дерево), і бічна панель
      статистики документа (вузли/глибина/унікальні ключі/найбільші гілки) ховається, поки
      воно активне. `Ctrl+Shift+F`/`Ctrl+Enter` форматують. Кожен інструмент тепер
      завантажується лише коли відкрита його вкладка (`React.lazy`), бо CodeMirror сам
      важить понад 500 КБ — головний бандл лишається компактним.
- [x] Етап 4 — інструмент Compare: чистий diff-рушій (`src/lib/diff.ts`, 40 тестів,
      усі опції порівняння — ignoreArrayOrder, arrayKeyField через `Map` без O(n²),
      ignoreCase, ignoredKeys з wildcard (`*.updatedAt`, `meta.*`), treatNullEmptyMissingAsEqual,
      numericTolerance, ignoreTypes) працює у Comlink-воркері (`diff.worker.ts`) з прогресом
      по фазах (розбір/розбір/порівняння) і робочим скасуванням. 2 панелі — кожна це повний
      `JsonInput` (валідація, м'який режим, форматування). Tree diff (кольори додано/видалено/
      змінено/однаково, однакові гілки згорнуті за замовчуванням, копіювання шляху) і таблиця
      відмінностей (сортування, фільтр за шляхом, «лише відмінності») з живим зведенням
      лічильників. Порівняння файлів > 2 МБ поки явно не підтримується (потребує спільної
      памʼяті між двома воркерами — залишено на етап 9 разом з рештою бюджету продуктивності).
- [x] Етап 5 — Compare: від 2 до 10 панелей («+»/«прибрати»). Для 2 панелей усе лишається як в
      етапі 4 (парний рушій, дерево з кольорами). Для 3+ панелей перша панель — референс: замість
      переписування diff-рушія під N документів `src/lib/diff-n-way.ts` просто запускає вже
      протестований парний `diffValues` N-1 раз (панель 1 проти кожної іншої, паралельно у
      воркері) і зводить результати в один набір рядків («Шлях | JSON 1 | JSON 2 | ... |
      Статус»); статус звужується до «однаково/відрізняється» — розрізнення додано/видалено/
      змінено з парного режиму на N>2 не переноситься 1:1. Новий вигляд Side-by-side — N
      синхронних колонок з підсвіткою рядків (зелений/червоний/жовтий/сірий), вигляд «Дерево»
      доступний лише для 2 панелей (при 3+ перемикається на «Таблиця» автоматично). Експорт
      звіту в Markdown-таблицю (готову для Jira/Confluence) і CSV через новий спільний
      `ExportBar` (Копіювати + Завантажити на кожен формат) — 5 нових тестів на
      `diff-export.ts`, 7 на `diff-n-way.ts`. Експорт вкладки у файл `.jsonstudio` — стаття
      з повного технічного завдання поза цим етапом, не робилась.
- [ ] Етапи 6–10 — див. технічне завдання.

## Приватність

Жодних мережевих запитів із вмістом документів. Продакшн-збірка містить
`Content-Security-Policy` (`connect-src 'self'`), що блокує будь-які вихідні з'єднання
окрім самого застосунку.
